# GPU 工作台

[English](README.md) · 简体中文

GPU 工作台是一款 macOS 应用，通过 SSH 查看 Linux 服务器的 NVIDIA 显卡占用，并在内置终端中打开 tmux 工作环境。每个快捷方式保存会话名、Conda 环境和工作目录。

## 构建与打开

Mac 需要 macOS 14 或以上、命令行开发工具，以及 Swift 6.1 或兼容工具链。在仓库根目录运行以下命令。首次构建会下载 `Package.resolved` 锁定的依赖。

```sh
bash Packaging/build-app.sh
open "dist/GPU 工作台.app"
```

脚本会为当前 Mac 架构构建应用并完成本地签名。在侧边栏底部的地球图标下选择 **简体中文** 或 **English**。添加第一台服务器前、打开终端后都可以切换。首次使用时默认为中文，选择会保存在这台 Mac 上。系统提供的控件沿用 macOS 的语言，终端内的输出沿用远程程序的语言。

## 连接服务器

1. 选择「添加服务器」，填写显示名称、主机和 SSH 用户名，再选择 Mac 上的私钥文件。使用标准 SSH 端口时留空即可。自定义端口和可选的 Conda 安装路径在「更多连接选项」中。
2. 获取 SSH 主机指纹，与管理员提供的值或已有的可信记录核对后，再保存连接。私钥带有口令时，可以通过「解锁密钥」将它加载到本机 SSH 代理。
3. 打开概览，查看每张 GPU 的利用率、已用和总显存，以及剩余显存。应用在前台约每五秒采样一次。监控中断时，概览保留最近一次读数及采样时间。

服务器需要支持 SSH 公钥登录，并提供 `/usr/bin/python3`（3.8 或以上）、Bash 和 tmux 3.2 或以上。GPU 监控使用 `nvidia-smi`，自动准备环境需要服务器已有的 Conda 安装，同步代码需要 rsync。服务器依赖 VPN 时，先让 Mac 接入对应网络。

## 打开工作环境

在「快捷方式」中新建一项，填写 tmux 会话名（例如 `research`）、Conda 环境名（`ml`）和服务器上已有目录的绝对路径（`/work/example-project`）。显示名称默认跟随会话名。

- **打开工作环境** 会在会话不存在时创建它，分为上方两个窗格和下方一个通栏窗格。三个新 Bash 都会进入所选目录并准备指定环境。遇到自定义激活脚本或无法核实的环境配置时，应用会提示如何手动激活。
- 再次打开快捷方式会接回已有会话，沿用原窗格和任务。遇到同名冲突时，可以换个会话名，也可以在核实会话属于自己后选择仅接回这一次。共用 Linux 账号时，单凭会话名无法判断是谁创建了会话。
- **重新连接** 会核对断开时的会话身份。原会话消失时，标签页会保留旧输出，由你决定是否新建同名会话。
- 可以勾选多个快捷方式，一次打开多个终端标签。按 `⌘1` 返回概览。关闭终端标签会断开对应的本机 SSH 连接。退出应用会关闭其余连接，远端 tmux 任务可以继续运行。

## 预演与同步代码

1. 在快捷方式旁选择「同步代码」，选取本地项目目录。远端目标是该快捷方式中已存在的工作目录。
2. 选择「预演」执行 rsync 试运行。清单先列出将覆盖的远端同名文件，再列出新增文件。同步范围限于 `.py` 和 `.sh` 普通文件，过滤规则会跳过工作台源码、应用包、构建输出及常见的私有目录或稿件目录。
3. 继续后可以看到目标服务器、目录以及两类文件的数量。可返回清单重新考虑，也可确认上传。正式传输前会再次核对清单，只上传审核过的路径。清单发生变化时需要重新预演。

预演不会在服务器上写入项目文件。确认上传后，应用会写入清单中的源码并保留远端多出的文件。上传清单仅在 Mac 临时保存。同步成功后，仍可在当前窗口核对这次的文件清单。

## 共享服务器与本机数据

应用使用系统 OpenSSH 客户端，并固定经核对的主机密钥。密钥变化时会阻止连接。服务器资料、快捷方式和可信主机密钥保存在 `~/Library/Application Support/GPUWorkbench/`，私钥留在原位置。

GPU 查询和会话管理通过 SSH 执行固定操作。应用不会在远端安装代理或写入启动脚本。Conda 环境和工作目录只对新建窗格中的进程生效。服务器可能保留正常的 SSH 审计日志和 tmux 运行状态，包括 tmux 的套接字。你在终端手动输入的命令按当前 Linux 账号的权限执行。

## 运行测试

```sh
swift test --disable-xctest
python3 -B -m unittest discover -s Tests/Remote -v
```

Python 测试使用本地临时会话。默认从 `PATH` 查找 tmux，也可通过 `GWB_TEST_TMUX` 指定可执行文件。如果需要测试真实的 Conda 激活过程，将 `GWB_TEST_CONDA` 设为 Conda 可执行文件的路径。

内置终端使用 [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)。
